# Echo v0.1.2

Maintenance release draft, 2026-11-09 (Asia/Shanghai).

- Check HTTP status before reading responses across all five provider adapters.
  Failed non-streaming calls also raise `ProviderError`, replacing silent `None`
  results for HTTP failures.
- Convert HTTP transport failures and explicit provider error payloads into
  messages without upstream bodies, URLs or credential values. The CLI reports
  failures concisely and exits with status 1.
- Fix Web streaming output: consume the server's `token` events, retain separate
  assistant bubbles across turns, and exclude failed or interrupted answers from
  saved assistant history. The next turn can start once the current conversation
  save finishes. User messages remain available for retry.

Verification uses synthetic configuration, HTTPX MockTransport and browser-local
response interception. No actual provider requests or personal data were used.
See `docs/VERIFICATION_0.1.2.md` for evidence and scope.

```sh
python -m pip install ./echo_chat-0.1.2-py3-none-any.whl
echo-chat --version
```

The application remains a local alpha prototype. Stored user data is plaintext;
real-provider compatibility and comprehensive upstream protocol validation are
not established by these tests. No PyPI publication was performed.
